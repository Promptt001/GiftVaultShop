# Gift Vault Shop 0.4.0 — static development review

The preview is ready for a manual test in a disposable world. This review found no change to the wallet format or TikTools connector, but it found a likely delay in how purchased items appear in the client. Do not treat the build or the earlier loading screen as a successful purchase test.

## Findings, in priority order

| Priority | Finding and evidence | What to do |
| --- | --- | --- |
| Check first | **The hotbar may update only after closing the shop.** `ShopMenu.purchase` changes the server's real inventory, but the open menu has only six display slots and does not send a player-inventory update. Minecraft 26.2's `ServerPlayer.tick` broadcasts the open menu; closing returns to the player inventory menu. This is a source-based prediction, not an observed loss or duplication of items. | With a free hotbar slot, buy torches and check the hotbar before and after closing. If the update is delayed, explicitly synchronize changed player slots after a successful purchase. |
| Check before streaming | **The fixed-size layout and mouse-only controls have limits.** `ShopScreen` uses a 294 × 206 panel, shortens long item names, and draws its own controls rather than using Minecraft's focusable widgets. There is no keyboard selection or confirmation. Large interface scales or small windows can clip the panel; the approved default names and prices still need a visual check with your stream layout. | Check all six cards at your actual capture size and game interface scale. Lower the interface scale if the panel clips. Keyboard navigation and adaptive layout are not part of this preview. |
| Check before streaming | **A gift can change the displayed balance while review is open.** `ShopMenu` sends each large points value in two signed 16-bit fields. Normally they arrive together; if a frame lands between updates when crossing a 65,536-point boundary, the display can briefly combine old and new halves. The server rechecks the real balance before buying, so it does not charge using that temporary display value. Custom high prices can also run into the card's text width. | The default prices are 5–75 points. If using unusually large custom values, verify the layout and balance update; use a single synchronized value in a future change if stable presentation at those ranges matters. |
| Upgrade | **A new world is not a new configuration.** `Settings.load` creates the default file only when it is absent from the game instance. Existing files aren't rewritten, and explicit event overrides remain in place. An existing `sparkle` cue now plays the new amethyst sound, and any missing `like` setting now falls back to quiet. | Use a clean instance for the default-catalog check, or back up and replace only the `shop` section. Leave the wallet and TikTools files alone. |
| Before a real broadcast | **Reconnect does not recover all missed gifts.** The existing connector guards rewards with recipient, final count, mapped gift and transaction checks. Its backlog limits prevent unbounded queues, but a gift overflow pauses rewards and closing the world discards pending events. The wallet retains processed identifiers indefinitely, so save size and the work of adding a new identifier grow over time. | Verify the feed in read-only mode first. Treat overflow and reconnect warnings as possible missing rewards; do not enable rewards in a valued world until the live fields and behavior are confirmed. |

## What was checked

- Traced item selection, cancellation, confirmation, inventory fit, debit and successful sound in `ShopMenu`. The server restricts the shop to the private single-player owner. It consumes confirmation before acting, checks funds again, and refuses a purchase that cannot fit in the 36 main inventory slots. A repeated confirmation without another selection is refused. The successful purchase uses a villager confirmation outside the gift cooldown; the default Rose uses an amethyst chime. Neither sound was listened to.
- Inspected Minecraft 26.2 compiled code without starting the game: menu button dispatch checks the current menu and runs on the server thread, screen initialization centers the panel, and menu data fields use signed 16-bit values. Wallet attachment name and format, settings loading and TikTools connector files did not change in this release.
- Read the earlier successful offline build log. Its standalone checks covered the exact six offers, wallet rules and serialization, alert options and a local simulated TikTools connection. Inspected the built mod archive for integrity, version, client and main entry points, declared dependencies, access rules and the default configuration. No new build or test process was started for this review.

For your manual run, follow [the playtest checklist](PLAYTEST.md). Prioritize catalog and review readability, one delivery and one debit on a double-click, full-inventory refusal, distinct sounds, and saving and reopening the world. A normal save and reopen does not establish crash recovery. No real TikTools connection, broadcast or audio mix was checked.
